== What this is, and how it works

*What it is.* A dated, signed record of what can be claimed about
*JaffaScript* at one exact commit. It makes no promises about the future; the
README covers that.

*What the project is.* JavaScript/TypeScript-syntax AffineScript. JaffaScript
is AffineScript with its `jaffa` face pre-selected. This repository carries no
compiler. Its executable surface is `bin/jaffa`, a shim that finds the
`affinescript` compiler and injects `--face jaffa`, plus examples and docs.

*How it stays trustworthy.* Every claim below comes from running the shim and
the repository's test scripts in the session that wrote this file. The anchor
names the exact commit. A signed git commit lands the file.

=== The nuance you must not lose

* All the real work happens in AffineScript. These results show that the shim
  reaches a working compiler and that the jaffa face accepts the example. They
  say nothing about the compiler's own test suite.
* The toolchain is an unreleased local build from a dirty branch (see
  <<verifiable-anchor>>). A release build may behave differently.

=== Known gaps, stated in the repo

* The capitalised `Justfile` still carries template recipes. `test`,
  `test-smoke`, `e2e`, `aspect`, `bench` and `lint` print "passed" or contain
  only `TODO` comments, and run nothing. *They are not evidence*, and this file
  cites none of them.

[#outstanding]
=== Outstanding, weak or refuted

* *The README's `eval` example fails.* `bin/jaffa eval examples/hello.affine`
  (also README lines 68 and 72) ends with "Runtime error: Unhandled effect:
  println" and a non-zero exit. The example declares an `IO` effect that the
  interpreter does not handle. `check` and `compile` succeed on the same file.
* *`just` cannot run here.* The root has both `Justfile` and `justfile`, and
  `just` refuses with "multiple candidate justfiles found". Neither the
  template recipes nor the small `justfile` (`check`, `run`, `build`, `hello`)
  can be called through `just` until one file is removed.
* *Aspect test: one false positive.* `bash tests/aspect_tests.sh` gives PASS=2,
  FAIL=1. The FAIL, "Dangerous proof patterns found", matches lines that
  *forbid* those patterns: `verification/proofs/README.adoc` lists `sorry`,
  `Admitted` and `unsafeCoerce` as banned, and `TypeSafety.v` says "NO
  Admitted allowed". The scanner cannot tell a ban from a use.
* *`tests/e2e.sh` checks nothing.* It exits 0 with PASS=0 FAIL=0 SKIP=0. It is
  still the uncustomised template.
* *Red CI at the anchor.* Of 8 check runs on this commit, 6 succeeded, 1 was
  skipped and 1 failed: `governance / Check Workflow Staleness`. It is not a
  required check; issue #66 tracks it.
